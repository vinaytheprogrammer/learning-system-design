Two technologies, one idea: standardize the box, then coordinate the fleet. Docker builds the box. Kubernetes runs the entire shipping yard. Here's everything you need for an interview — in plain language.

CONTAINER NO. 01 · The Why

Before the code: why does software break when it moves?

Before learning any commands, you need to understand the problem Docker was built to kill. It's not a bug in your code — it's a mismatch between worlds.

1.1The "It Works on My Machine" Problem

Your laptop and a cloud server are two different worlds pretending to be the same one.

your-laptop
$ python --version
Python 3.11.4
$ ✓ runs perfectly
⚡︎
prod-server
$ python --version
Python 3.8.2
$ ✕ ModuleNotFoundError

Same code. Different OS version, different dependency versions, maybe a missing library entirely. The app didn't change — the ground underneath it did.

1.2The Shipping Container Analogy

Before the 1950s, cargo was chaos — crates, barrels, and sacks of every shape, each needing different handling at every port. Then the industry standardized the box. Watch what happens.

mismatched cargo — every crane needs to improvise

Once every box is the same standard shape, any ship, train, or crane can move it without caring what's inside. Docker is that standard box for software — it packages your app plus its exact dependencies into one unit that runs identically anywhere a container engine exists.

1.3Containers vs. Virtual Machines

A Virtual Machine is like renting an entire house — your own plumbing, your own wiring, a full operating system, just for you. A Container is like renting a room in a shared apartment — the building's infrastructure (the OS kernel) is shared, so your room is lighter, cheaper, and ready to move into instantly.

COPY . .
CMD ["node", "server.js"]
terminal
$ docker build -t my-app .      // recipe → frozen image

2.2Layered Architecture

Docker images are built like stacked Lego bricks. Each instruction adds one brick on top of the last — and Docker caches every brick separately. Try changing just the top one.

COPY . . (rebuilds)
RUN npm install (cached)
COPY package.json . (cached)
FROM node:20 (cached)
Click to see what Docker actually rebuilds.

Three bricks stayed frozen. Only the top one — your actual code — got rebuilt. That's why Docker rebuilds are fast and disk-efficient: identical layers are reused, never duplicated.

CONTAINER NO. 03 · Why Kubernetes

From one container to a whole fleet

Docker gives you one shipping container, perfectly packed. Great. Now your app goes viral.

500containers to run
50physical machines
0humans who can track it by hand

3.1The Orchestra Analogy

Each Docker container is one musician playing one instrument. Fine alone. Put 500 of them in a hall with no coordination and you get noise — people out of sync, too loud, some silent. Kubernetes is the conductor. It never plays an instrument itself — it just makes sure everyone plays together, on beat, and nobody goes quiet without being replaced.

+ Traffic spikes → extra replicas spin up automatically, then scale back down
CONTAINER NO. 04 · Core Concepts

The vocabulary, with pictures

Four terms carry almost every Kubernetes conversation. Here's each one, made physical.

Pods — the spaceship

The smallest deployable unit in Kubernetes. Think of a spaceship holding one or more astronauts (containers) that share the same life support — same network address, same storage. Usually one astronaut per ship; sometimes a helper rides along.

DESIRED REPLICAS
Deployments — the manager

A Deployment is a manager with one obsession: "I always want exactly 3 copies running." One dies? "Go hire a replacement, immediately." Ship a new version? It replaces Pods gradually so the app never fully goes dark.

Internet

Services & Ingress — receptionist & front door

Pods are born and die constantly, so their addresses keep changing. A Service is a receptionist with one stable address, always routing you to a healthy Pod. Ingress is the front door for outside internet traffic, directing each visitor to the right Service.

Nodes & Clusters — the warehouse floor

A Node is one physical or virtual machine — one worker station on the warehouse floor, with its own CPU, memory, disk. A Cluster is the entire warehouse: every Node working together as one team, centrally managed by Kubernetes.

CONTAINER NO. 05 · Interview Prep

Common questions & beginner traps

5.1State vs. Stateless — where does the data live?

Containers are forgetful by design. When a container is destroyed, anything written inside its own filesystem disappears with it. Try it below.

CONTAINER
user-photo.jpg
→
VOLUME
An uploaded file sits in the container. What happens when it restarts?
Gotcha

Without a Volume, restarting a container doesn't "reboot" your data — it erases it. A Volume is like plugging in an external hard drive: it lives outside the container's lifecycle, so data survives crashes, restarts, even a container rescheduled onto a different machine.

5.2Configuration Management

You shouldn't rebuild an image just to switch from a test database to a live one. Settings should live outside the image.

.env (staging)
DATABASE_URL=postgres://test-db.local:5432
LOG_LEVEL=debug

Same image, same Dockerfile — only the Environment Variables change between tabs. In Kubernetes, a ConfigMap does the same job: configuration lives separately from the image, so updating settings never means a rebuild.

5.3Summary Checklist

If an interviewer asks "what's the difference between Docker and Kubernetes," say this:

  1. Docker packages an application and its dependencies into a standardized, portable container, solving the "it works on my machine" problem.
  2. Docker is great at running one container, but has no built-in way to manage hundreds of them across many servers.
  3. Kubernetes is an orchestration system that manages, schedules, and coordinates containers across a cluster of machines.
  4. Kubernetes adds self-healing — replacing crashed containers — and auto-scaling — adding copies under load — without human intervention.
  5. In short: Docker builds and runs the box; Kubernetes is the conductor coordinating thousands of boxes at scale.
